# Planned database schema

This is the target PostgreSQL schema. It is deliberately close to the existing Supabase data model so that data migration stays simple.

## Tables

### `users`

| Column | Type | Rules |
| --- | --- | --- |
| `id` | UUID | Primary key, generated by the database |
| `name` | text | Required |
| `email` | text | Required, unique, normalized to lowercase |
| `password_hash` | text | Required; never store a plaintext password |
| `created_at` | timestamptz | Required, default now |
| `updated_at` | timestamptz | Required, default now |

### `sessions`

| Column | Type | Rules |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `user_id` | UUID | Required foreign key to `users`, cascade delete |
| `token_hash` | text | Required, unique; store only a hash of the session token |
| `expires_at` | timestamptz | Required |
| `created_at` | timestamptz | Required, default now |

### `solutions`

| Column | Type | Rules |
| --- | --- | --- |
| `id` | UUID | Primary key |
| `user_id` | UUID | Required foreign key to `users`, cascade delete |
| `title` | text | Required |
| `description` | text | Required |
| `problem_description` | text | Required, default empty string |
| `solution_steps` | text | Required, default empty string |
| `status` | text | `open` or `resolved` |
| `difficulty` | text | `easy`, `medium`, or `hard` |
| `tags` | text[] | Required, default empty array |
| `code_snippets` | jsonb | Required, default empty array |
| `created_at` | timestamptz | Required, default now |
| `updated_at` | timestamptz | Required, default now |

### `favorites`

| Column | Type | Rules |
| --- | --- | --- |
| `user_id` | UUID | Required foreign key to `users`, cascade delete |
| `solution_id` | UUID | Required foreign key to `solutions`, cascade delete |
| `created_at` | timestamptz | Required, default now |

Use `(user_id, solution_id)` as either the composite primary key or a unique constraint. A person may favorite a solution once.

## Required indexes and constraints

- `users.email` must be unique.
- Index `sessions.user_id` and `sessions.expires_at`.
- Index `solutions.user_id, created_at DESC`.
- Index `favorites.user_id` and `favorites.solution_id`.
- Validate `solutions.status` and `solutions.difficulty` with database check constraints.

## Authorization rule

Every solution and favorite query must derive the user id from the current server session, then scope the query by that id. Never trust a user id supplied by a browser form or URL.

## Migration note

Existing `solutions` and `user_favorites` records can be exported from Supabase and imported after users have been mapped. Existing account passwords should not be migrated; affected users must set a new password in the new system.
